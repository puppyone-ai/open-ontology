# 01 产品侧工作形态：协作方式、基线与验收层级

> Status: Accepted（据 2026-10 至 2026-11 的实际运行复盘整理）
> Owner: Open Ontology Engineering
> Last reviewed: 2026-11-06
> 适用：v0.2 产品闭环开发（[Plan](../../specs/product-loops-v0.2-plan.md)）。客户交付线另行管理，本文不含任何客户信息。

本文记录前一阶段真正起作用的协作方式和被证明是浪费的做法，作为 v0.2 产品开发的工作约定。它不替代 [v0.1 Plan](../../specs/open-ontology-v0.1-plan.md) 的任务卡规范，只在其上做收敛。

## 1. 角色

| 角色 | 负责 | 不做 |
|---|---|---|
| 主线程（协调者） | 范围、接口契约、任务卡冻结、调度、集成、最终验收；短修复、定位、监控、文档收口 | 不把短任务外包；不为凑并发派单；不消费他人半成品 |
| 子智能体（执行者） | 领取一张冻结的长程任务卡，独占写域内完成端到端能力并交付固定证据 | 不再派生自己的子智能体；不改写域外文件；不自行扩大范围 |
| 独立审阅 | 在闭环里程碑对固定 SHA 做审阅 | 不审普通中间功能（`deferred_to_integration`） |

执行者模型和并发数随人类最新指令变化，计划文档只写“当前约定见状态文件”，不再把具体模型名、并发、等待秒数抄进多份文档。

## 2. 派单规则

1. **只派长程、可独立交付、写域独占的工作。** 典型：一个数据库引擎的完整版本矩阵、TUI 向导、token 续期协议。短修复和集成留主线程。
2. **一个能力一个 owner。** 每个引擎一位执行者负责从连接、分块、增量、到 Self-build/Pack/Gateway 对话的完整链；不再拆 driver 与 consumer 两人。
3. **共享文件单 writer。** 根 `Cargo.toml`/`Cargo.lock`、`migrations/`、共享 trait（`crates/oo-connectors` 公共接口）、`support-matrix.yaml` 只由主线程或明确指派的一人写；其他人提交补丁说明，由 writer 合入。
4. **消费方只用固定 SHA。** 不编译别人正在改的工作区，不恢复别人的改动。
5. **任务卡冻结字段**（沿用 `.codex/skills/codex-grok/references/task-template.md`）：Plan 条目、实际输入、依赖 SHA、接口、独占写路径、资源上限、成功与必要失败用例、退出条件、交付物、清理责任。接口需要变化时先改卡，再改代码。
6. **等待方式。** 派出后由完成通知唤醒；不做短间隔轮询、不 tail 日志、不以“安静太久”为由杀进程。
7. **并行上限按实际收益定。** v0.2 建议同时在跑的执行者 ≤ 5：引擎矩阵最多 3 条，L1/L2 各 1 条；S0–S1 因接入车道提前启动放宽到 6（Plan §2，ledger E016）。

## 3. 状态文件：一份当前状态 + 一份决策日志

前一阶段的主要浪费是覆盖条文在 6 个文件里累积（`CONTROL.md`、`control-state.json`、`GOAL.md`、`HANDOFF.md`、`INDEX.md`、`PRODUCT-LOOPS.md`），各自过期、互相矛盾。v0.2 改为：

| 文件 | 内容 | 规则 |
|---|---|---|
| `execution/v0.2/state.json` | 当前 sprint、每张任务卡 owner/写域/状态、每个闭环的验收层级 | 唯一当前真相；覆盖写，不追加历史 |
| `execution/v0.2/decisions.md` | 人类指令与范围变化，按时间追加 | 只追加；每条一句话 + 生效范围 |

| Plan 文档 | 任务定义与退出条件 | 内容变化走 PR，不在顶部堆“最新覆盖”段落 |

## 4. 验收层级

沿用四级，不能互相替代：

| 层级 | 含义 | 由谁给 |
|---|---|---|
| Author complete | 作者在固定 SHA 上完成实现与真实测试，交付 REPORT/原始退出码/SHA256SUMS/资源回执 | 执行者 |
| Fixed review | 独立审阅者在同一 SHA 复核关键行为 | 审阅者 |
| Integration accepted | 主线程把能力接进完整闭环并在真实链路跑通 | 主线程 |
| Release ready | 打包、安装、文档、升级路径都通过，可对外发布 | 主线程 + 人类 |

不算通过的东西：CLI 退出 0、HTTP 200、零个测试、容器启动、文件存在、fixture 改名、模型给出了最终文字回答。失败记录修好后保留，不改写为成功。

## 6. 必须保留的硬规则

1. 源端只读、零写；读取预算与压力保护是硬边界，不为提速关闭。
2. 不截数据、不跳表、不设业务容量上限；分页、分块、暂存、超时是内部资源预算。
3. 查询成功、数据已发布、源端最新、业务回答正确是四个不同状态，分别记录；查不到/失败/NULL 不写成零。
4. C5（范围摘要差分）不叫 CDC；读到 SCN/LSN 不等于 CDC 已工作；不伪造 ACK、不重置位点、不静默重建 slot、不静默回退全量。
5. 能力不可推导：协议兼容、同家族、同产品另一版本，都不能继承证据。
6. 失败周期不延长 deadline、不清位点、不补造成功、不删历史。
7. 秘密与客户数据不进 Git、argv、日志、Pack；token 只存文件引用，文件 0600。
8. 未知来历的进程或容器标 unknown，不 kill、不清理 volume。
