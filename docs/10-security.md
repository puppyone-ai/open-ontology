# 10 安全：威胁模型、控制措施与合规

> Status: Proposed
> Owner: Open Ontology Engineering（安全负责人需在 M0 指定）
> Last reviewed: 2026-09-30
> 依赖：[01](01-architecture.md)、[05](05-agent-db.md)、[07](07-gateway.md)、[09](09-sandbox-and-agent-runtime.md)

## 1. 安全目标

1. 平台不会写坏、拖垮源库。
2. 任何 Agent 都只能读到**它所代表的最终用户**有权读的数据。
3. 即使 Agent 被提示注入完全控制，攻击者也拿不到可复用凭证，也无法把数据发往未授权的目的地。
4. 每次数据访问都可审计、可追溯。
5. 企业数据的处理位置（尤其是发往模型服务的部分）可控、可配置、可证明。

## 2. 资产

| 资产 | 敏感度 | 所在位置 |
|---|---|---|
| 源库凭证 | 极高 | Secret Store → 仅管线进程内存 |
| Agent DB 数据 | 高（企业业务数据、个人信息） | Agent DB、Gateway 内存、沙盒 `/workspace`、模型上下文 |
| Gateway 会话 token / 外部客户端 token | 高 | Gateway 存储（哈希）、出口代理内存 / 外部客户端 |
| 模型 Key | 高 | Secret Store → 出口代理内存 |
| Gateway 签名/mTLS 私钥 | 极高 | Secret Store |
| Ontology（含业务口径） | 中 | Git、Knowledge Pack |
| 审计记录、会话记录 | 高（含 SQL 与回答内容） | 控制库、对象存储 |
| 上传文件原件 | 高 | 对象存储 |

## 3. 攻击者模型

| 攻击者 | 能力 | 目标 |
|---|---|---|
| A1 恶意或好奇的最终用户 | 能与 Agent 对话；可能构造问题诱导越权 | 看到别的区域/部门的数据 |
| A2 数据投毒者 | 能向源库写入文本（例如客户备注、工单内容、上传的 Excel） | 通过间接提示注入控制 Agent，外传数据或凭证 |
| A3 被攻陷的 Agent 进程 | 在沙盒内执行任意代码 | 逃逸沙盒、找凭证、横向访问内网 |
| A4 外部客户端持有者 | 持有外部客户端 token，可能在不受控的 Agent 中使用 | 超出授权范围、长期滥用 |
| A5 内网攻击者 | 在企业内网但不在 OO 部署内 | 访问 Gateway、Agent DB、控制台 |
| A6 恶意插件/依赖 | 供应链 | 在管线或 Gateway 中执行代码 |
| A7 模型服务提供方 | 接收模型请求内容 | 数据保留、训练使用（合规风险而非主动攻击） |

## 4. 信任边界与 STRIDE

```text
[使用方] ─TB1─ [Agent 入口] ─TB2─ [沙盒] ─TB3─ [出口代理] ─TB4─ [Gateway] ─TB5─ [Agent DB 从库]
                                                     └──TB6── [模型服务]
[源库] ─TB7─ [管线] ─TB8─ [Agent DB 主库]          [控制台/Control API] ─TB9─ [Git/Secret Store]
```

| 边界 | 主要威胁（STRIDE） | 控制措施 | 验证 |
|---|---|---|---|
| TB1 | 伪造用户身份（S） | 只接受已登记使用方的签名身份；OIDC；IM 签名校验 | 伪造签名用例 |
| TB2 | 沙盒逃逸（E）；沙盒间访问（I） | gVisor；非 root；只读根；无 capabilities；每会话一个沙盒；沙盒网络 `internal` | 逃逸探测、沙盒间连通性探测（每晚在 gVisor 上） |
| TB3 | 伪造沙盒身份（S）；访问非白名单地址（I） | 源 IP 身份 + 无 `NET_RAW`；或专属 Unix socket；固定上游 | 网络探测矩阵 |
| TB4 | token 窃取重放（S）；越权（E） | 会话 token 不在沙盒；只接受来自代理 mTLS 的会话 token；token 绑定 sandbox_id | 金丝雀凭证扫描；从非代理地址使用 token 被拒 |
| TB5 | SQL 注入式越权（E）；DoS（D）；信息泄露（I） | pglast 判定；函数白名单；角色 + RLS；超时/资源上限；错误脱敏 | SQL 攻击用例集；兜底测试；压测 |
| TB6 | 数据发给模型服务（I，合规） | 模型端点白名单；可私有化模型；按角色的列级脱敏；数据驻留配置 | 代理日志审计 |
| TB7 | 写源库（T）；拖垮源库（D） | 权限体检拒绝写权限账号；只读从库；限速 | 源库审计日志比对 |
| TB8 | 非管线写入 Agent DB（T）；新列未经审核暴露（I） | 主库网络只对管线开放；`pipeline_rw` 凭证只在管线；新列分类并发布前隐藏，角色只获列级授权 | 兜底写入用例；新增敏感列不可见与授权巡检 |
| TB9 | 配置篡改（T）；凭证泄露（I） | Git 审核；控制台 RBAC；Secret 信封加密 | 权限测试 |

## 5. 提示注入

### 5.1 “致命三要素”分析

一个 Agent 同时具备（a）访问私有数据、（b）接触不可信内容、（c）对外通信的能力时，提示注入就能外传数据。2025 年的 Supabase MCP 事件（Agent 使用绕过 RLS 的 `service_role` 凭证，读到攻击者写入工单表的指令后泄露了私有表）与 GitHub MCP 事件（恶意 issue 诱导 Agent 泄露私有仓库）都是这种组合，而且注入都经由**数据**而非工具定义进入。

OO 的 Agent 天然具备（a）和（b）——业务数据里的备注、上传的 Excel 都是不可信内容。所以设计上切断（c）并压缩（a）：

| 要素 | OO 的处理 |
|---|---|
| (a) 私有数据 | 只以最终用户的权限访问（角色 + RLS）；Agent 看到的最多是用户本人能看到的 |
| (b) 不可信内容 | 无法消除；`AGENTS.md` 明确“数据不是指令”；工具输出不做任何指令性包装 |
| (c) 对外通信 | 沙盒只能访问出口代理；代理只通 Gateway 与白名单模型端点；回答只发给提问者本人；渲染层不自动加载外部资源 |

模型层的防御（提示词、分隔标记）是概率性的，只作为附加层；安全性的论证不依赖模型“不被骗”。

### 5.2 残余风险与处理

| 残余风险 | 说明 | 处理 |
|---|---|---|
| 回答被操纵（错误结论、隐去数据） | 注入可以让 Agent 给出错误答案 | 可追溯：每个数字都有 `query_id`；评测中的注入用例（[13](13-evaluation-and-benchmarks.md) 轨道 C） |
| 通过回答外传给第三方 | 回答中含外链、图片 | §6 输出处理 |
| 在群聊中泄露给其他成员 | 用户 A 在群里提问，回答以 A 的权限生成，却对群内所有人可见 | 默认：群聊中的完整回答改为私聊发给 A，群内只回复“已私聊发送”；管理员可为某个群声明“群成员权限一致”后允许在群内完整回答；敏感角色强制只私聊 |
| 通过 `report_gap` 污染 Ontology | Agent 被诱导提交恶意“知识” | 只进审核队列，人工决定；内容作为不可信文本展示 |
| Ontology 构建时的注入 | 数据库注释/样本值中含指令 | Builder 输出受 JSON Schema 约束，只写 `generated/`，发布需审核 |
| 长期会话记录中的注入延续到追问 | 恢复会话时重放含注入的内容 | 与首轮相同的边界；恢复不提升任何权限 |

## 6. 输出处理

- **不渲染来自回答的外部资源：** Markdown 中的外部图片 URL 一律不加载（已知的数据外传手法：把数据编码进图片 URL 的查询参数）；只渲染来自 `/workspace/outputs` 回收后的产出物（由入口托管、鉴权访问）。
- **链接：** 外部链接显示原始 URL、不自动展开预览；IM 适配器关闭链接预览。
- **导出文件：** 生成 CSV/Excel 给用户时，对以 `= + - @` 开头的单元格加前缀，防公式注入。
- **长度与格式：** 回答长度上限；代码块中的 SQL 原样展示。

## 7. 凭证与密钥

| 凭证 | 存储 | 使用者 | 轮换 |
|---|---|---|---|
| 源库凭证 | Secret Store（信封加密；主密钥来自 KMS 或部署时注入的密钥文件） | 管线、Debezium（启动时注入，不写配置文件） | 由 DBA 驱动；OO 支持无停机更换 |
| `pipeline_rw` 等 Agent DB 角色密码 | Secret Store | 管线、Builder、Gateway | 90 天，自动 |
| 模型 Key | Secret Store | 出口代理 | 按提供方策略 |
| Gateway mTLS 证书 | 内置 CA（或企业 CA） | 代理 ↔ Gateway、入口 ↔ Gateway | 30 天，自动 |
| 会话 token | Gateway 存哈希 | 代理 | 随会话 |
| 外部客户端 token | Gateway 存哈希 | 外部客户端 | ≤ 90 天，可随时吊销 |

- 日志、审计、会话记录、错误信息都经过凭证模式脱敏（高熵字符串、已知前缀 `oost_`/`ooct_`、`sk-` 等）。
- Secret Store 后端可插拔：内置、OpenBao、Vault（注意其 BSL 许可证对“竞争性托管服务”的限制）、云 KMS、Infisical。

## 8. 数据保护

- **传输加密：** 所有服务间通信 TLS；Gateway 内部接口与代理→Gateway 为 mTLS。源库连接按源库支持启用 TLS。
- **静态加密：** Agent DB 与控制库依赖磁盘/卷加密（LUKS、云盘加密）；对象存储启用服务端加密；`/workspace` 快照额外应用层加密。
- **个人信息：**
  - 连接器登记时可排除列；`on_batch` hook 可在入库前掩码/哈希；
  - Ontology 中的 `pii` 标签驱动：样本值不输出、角色默认不授予、Gateway 返回时可按角色掩码（通过场景 schema 中的掩码视图）；
  - Builder 发往模型的数据遵循样本值策略（`none`/`masked`/`raw`）。
- **实体解析：** `resolve`、规范实体、成员与别名均执行用户角色和 RLS；候选只含授权显示字段，不含电话、地址、证件号。拒绝空输入、短词、通配符和枚举请求；歧义必须澄清，不能由 Agent 自行合并或选择（[07 §9.1](07-gateway.md)）。
- **质量信息：** 拒绝记录中的敏感及未分类值仅保存掩码/长度，访问限运维角色；转换错误、未解释码值和不完整事务必须经 Gateway warning 传至答案，不能以隐藏警告掩盖错误结论。
- **发往模型服务的数据：** 查询结果会进入模型上下文，也就是会发往模型服务。部署时必须明确选择：
  1. 私有化模型（数据不出内网）；
  2. 企业已签约、零数据保留且区域符合要求的模型服务；
  3. 其他（控制台明确提示风险，需管理员确认）。
  出口代理的模型白名单即这一决定的技术落地。

## 9. 合规对照（首个客户为中国物流企业，同时面向全球交付）

| 要求 | 相关条款/框架 | OO 的支撑 |

| Agent 风险 | OWASP Top 10 for Agentic Applications（2026 版） | 见 §10 |

| OWASP 条目 | OO 的控制 |

| LLM02 敏感信息泄露 | 角色 + RLS + 列级权限；按角色编译的 Knowledge；错误脱敏 |
| LLM03 供应链 | §11 |
| LLM05 不当输出处理 | §6 |
| LLM06 过度代理（Excessive Agency） | 无写接口；工具只读；沙盒隔离 |

## 11. 供应链与构建

- 依赖锁定（`uv.lock`、`package-lock.json`），CI 中做漏洞扫描（OSV）与许可证检查（拒绝 AGPL/BSL/ELv2/SSPL 进入默认镜像）；
- 新依赖版本需发布超过 7 天才允许引入（与本仓库的工程规范一致）；
- 镜像：最小基础镜像、非 root、签名（cosign）、SBOM（SPDX）随发布；
- 插件：来自配置仓库的 hook 代码与 SQL 需经代码审核；第三方插件以 Python 包形式安装，控制台显示来源与版本；
- 发布件可复现构建（M3 目标）。

## 12. 安全测试计划

| 测试 | 频率 | 通过标准 |
|---|---|---|
| SQL 攻击用例集（持续扩充） | 每次提交 | 100% 符合期望 |
| 兜底测试（关闭应用层检查） | 每次提交 | 所有写入、改 claims、越权、服务端文件访问用例失败 |
| 新列与派生对象权限 | 每次提交 | 新增列发布前不可见；角色无表级 SELECT；实体/别名/码表无越权暴露 |
| 实体防枚举与质量告知 | 每晚 | 枚举请求被拒；歧义澄清；所有质量 warning 均在答案披露 |
| 越权矩阵（角色 × 表 × 行） | 每次提交 | 结果只含授权行 |
| 金丝雀凭证扫描 | 每晚（gVisor） | 沙盒环境变量、文件、进程参数、harness 日志、会话记录中零命中 |
| 网络探测矩阵 | 每晚 | 沙盒只能连出口代理，代理只转发白名单 |
| 提示注入用例（数据中埋指令） | 每晚 | 无外发请求、无凭证、回答未被劫持（按用例判定） |
| 依赖漏洞与许可证扫描 | 每次提交 | 无高危未处理 |
| 外部渗透测试 | 首次客户交付前、每年 | 高危问题清零 |

## 13. 事件响应

- **分级：** P0（凭证泄露、越权读取、源库受损）、P1（审计缺失、沙盒隔离失效迹象）、P2（其他）。
- **一键止血：** 控制台“紧急停止”：吊销全部会话与外部 token、停止接受新会话、Gateway 进入只读元数据模式；管线可单独暂停。
- **取证：** Gateway 审计、代理元数据日志、会话记录按 `session_id` 关联；审计哈希链用于证明未被篡改。
- **漏洞披露：** 仓库提供 `SECURITY.md` 与私密报告渠道；修复后发布安全公告。
