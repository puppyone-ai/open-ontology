# DBA grants and prerequisites

Generated by `python3 tools/docs/gen_dba_grants.py`; do not hand-edit SQL.
These are **source templates**, not a script to execute wholesale. Braces are Rust substitutions; account, schema and table quoting is performed by the connector. Run `oo doctor --config stack.yaml --json` for observed `capabilities.*.requirements`: `name`, `observed`, `required`, and `dba_statement`. A null statement means no automatic remedy is supplied.

A DBA applies only the requirements for the requested capability, on a separate administrative connection. Never give the product reader DDL/DML authority merely to clear doctor. Parameter changes, restarts, supplemental logging, slots and publications require DBA review. Re-run doctor afterward.

Version headings identify contract branches, not new engine/version test results. The support matrix remains the acceptance authority.

## MySQL 5.7 / 8.0 / 8.4 / 9.x

Snapshot needs SELECT; binlog C1 additionally needs replication privileges, ROW logging and sufficient retention. The dialect selects version-specific status/parameter syntax: 5.7 uses SET GLOBAL plus my.cnf and expire_logs_days; 8.0+ uses SET PERSIST and binlog_expire_logs_seconds. 8.4+ uses SHOW BINARY LOG STATUS. The mysql-binlog feature is not enabled by default (D10).

## Oracle 11g / 21c / 23ai

11g uses SELECT ANY TRANSACTION for LogMiner; 21c/23ai use LOGMINING and CDB/PDB-aware grants. C5 uses table SELECT/FLASHBACK and catalog access. LogMiner C1 is explicit opt-in, never auto-selected. D11a permits Oracle's internal DML on SYS/SYSTEM LOGMNR-prefixed objects and same-session COMMIT during LogMiner; the reader's top-level statements remain SELECT and DBMS_LOGMNR calls only. This is not literal zero internal writes. Default C5 requires its separate zero-business-write audit.

## Contract gaps

SQL Server does not yet emit a complete reader GRANT list per server version. Oracle account/session prerequisites and actual catalog-view requirements depend on the observed container and selected tables. These templates cannot replace the live doctor report. MongoDB/OpenSearch use non-SQL authorization contracts and are outside this SQL grant list.
