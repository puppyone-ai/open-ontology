The numbers of the section below were measured against the earlier labels (without the departments) and are kept as history.


`tools/oo-test/super_ontology_eval_live.py` (wrapping `cargo test -p oo-docs --test eval_live`): a real
`oo-docs-engine`, the Docling sidecar container and, for the ON run, the real model egress configured through
`PUT /v1/docs/config/model` with `file:` references only (the owner's endpoint and key files, never read or
printed by the tooling). Every file of the set (md, txt, csv, xlsx, docx, pptx, pdf) is parsed by its real parser.
The engine's output is written in the labels format (`predictions/`) and scored by `oo-eval docs` against the labels.
`--golden DIR` scores another labelled set (the held-out one), `--keep-out DIR` keeps the raw predictions.

Two views of the same run:

* `report.*`: every candidate the engine produced that was not rejected (the extraction output, drafts that wait
  for a person included).
* `report-published.*`: only facts in a published version, and the entities they connect plus every Document. This is
  what a pack can contain and what a person sees as the ontology; **the acceptance numbers are these**.

Two sets:

* `model-off/`, `model-on/`: the golden set (`testing/super-ontology/golden`, 51 files, used for tuning).
* `holdout/model-off/`, `holdout/model-on/`: the held-out set (`testing/super-ontology/holdout`, seed 20270301,
  46 files), generated by `gen.py --variant holdout`: the same formats and label schema, a different cast (every
  person, organization, project, topic, term, event and place renamed, the calendar one year on, the weekday words
  changed, five documents left out). It was scored once, after the tuning on the golden set was finished. It keeps
  the golden set's *structure* (same document kinds, same sentence patterns), so it checks that nothing depends on the
  golden names; it cannot show that a rule fitted to the golden *phrasing* also holds for other phrasings.

Reading of the table:

* **Target, golden set, model on, published view: met.** Entities (all core types) P 0.913 / R 0.903, facts P 0.854 / R 0.807. The margin on the golden facts precision is small (+0.004): the model's output varies from run to run at temperature 0 (golden runs of the last day gave facts P 0.843 to 0.871).
* **Held-out set (scored after the tuning), model on, published view: NOT met (facts R 0.734).** Entities 0.905 / 0.864, facts 0.853 / 0.734. The entity numbers are within 0.04 of the golden ones. The facts recall gap (0.07) is the Topic and Event entities: 2 of the 10 on golden and 0 of 10 on the held-out set were established (the model proposes them in one file and the engine publishes a model entity only when its facts clear 5.3), and a Topic that is not established gets none of its mentions (about 20 facts). That is the model's variance at the threshold and not a golden name in the code (a held-out run before the last two changes, which also linked by nickname, gave facts R 0.831); it is still a miss of the strict target on the held-out set and is reported as one.
* **Two readings that do not meet it on either set, stated here and not hidden:**
  1. The candidate view (everything the engine produced that was not rejected, the model's proposals that wait in the review queue included): entities P 0.688 golden / 0.686 held-out, facts P 0.819 / 0.811. The published view is what a pack and the entity list show; the candidates are the queue's input.
  2. Entities without the `Document` type (the 51 Documents are trivially right and lift every entity number): P / R 0.805 / 0.786 on golden, 0.789 / 0.714 on the held-out set. All 8 false positives are 7 department Organizations (`rules/1` 5.1 makes a department of a people table an Organization with `member_of`; the labels have no department) and 1 Project (a budget row; the labels call it a Topic). They are not model errors. Either the labels get the departments or 5.1 changes; neither was done here.
* Model off (rules only), reported separately and without errors: golden entities 0.908 / 0.850, facts 0.926 / 0.621; held-out 0.902 / 0.841 and 0.920 / 0.627. All files `published`, no failed state.
* Supersession (D17): 4 of 4 gold links correct on both sets (before: 0 of 4; the held-out model run predicts 2 more links than the gold has). Conflict (D57): the engine records the integrity violation and keeps both owners out of the published version by design, so the published view has no pair to show (0/1); the candidate view finds it (1/1).
* Red team: 0 canary and 0 red-team-only name hits in every run and view.
* `about` is the weakest relation (P 0.64 / R 0.62 published on golden): the labels list the subjects the author chose for a document; most misses have a Topic or an Event (outside the core range of 10 DOC-G1) as object or a Term the engine did not establish, and most false positives are projects a meeting minute or a table lists that the labels do not call its subject.
* Links are made by canonical name only: a nickname or a given name would show a reader of one scope who the entity is from files outside it, and the leak guard stops that pack (the L4 coverage step found it). The labels count 11 alias mentions of the notes on golden; they stay unlinked.

Run facts: see each `run.json` (calls count every wire retry; daily limit 2,000, per file 20, never limited). The owner's endpoint drops about half of its TLS connections on some days; a call that fails on the wire is retried up to four times. One golden file stays `indexed` with the model on (its model facts wait in the review queue); the others are `published`.

L4 target with the model: P >= 0.85, R >= 0.75. **Not met**, recorded as measured:

* Entities: recall is above target in every run (0.82 off, 0.86 on, published). Precision meets it only with the model
  off (0.874). With the model it falls to 0.77 (published) because the model names Organization, Event and Topic
  entities the labels do not have (Organization 8 FP, Event 2, Topic 1 among the published; 8, 19 and 14 among all
  candidates). The held candidates are what keeps published precision above the all-candidates number.
* Facts: precision with the model is 0.57 and recall 0.33. The gold set has 441 facts, 292 of them `mentions` and
  113 `about` links from a Document to an entity; the rules find 0.29 and 0.08 of them and the model adds to
  `mentions` (0.37) but little to `about` (0.15). `owns` and `member_of` lose precision with the model (0.19 and 0.20
  published, against 0.25 and 0.29 off): the model writes ownership and membership statements the labels do not.
* Supersession: gold 4, predicted 3, scored `correct` 0 in both runs, although the `supersedes` facts themselves match
  (3 of 3 with the model off, `supersedes` row above); the evaluator's link matcher and the exported
  `superseded_by` pairs disagree and this was not investigated here. Conflict (D57): gold 1, predicted 0 (the
  evaluator reads predicted `conflict` records; the engine's `constraint_violation` rows are not exported).
* Red team: 0 canary and 0 red-team-only name hits in every view.

Run facts (model on): 205 calls (this run) against the Drive's daily limit of 2,000 and the per file cap of 20, none
limited (`files_limited` 0), 77,626 tokens in and 47,878 out, about 11 minutes with 4 extract_llm workers. 47 files
`published` and 4 `indexed` (every fact of those files waits for a person in the review queue). The owner's endpoint
drops roughly half of its TLS connections (`SSL: UNEXPECTED_EOF` after 5 s, observed outside the engine with a
two-line probe too), so a call that fails on the wire is retried up to four times with three seconds between tries;
the counters in `run.json` count every call. Two earlier ON runs were discarded: the first produced
no model fact at all because the strict schema rejected `""` in optional fields (fixed, with a test), the second
had an egress that served one request at a time and refused the engine's parallel workers (fixed, with a test).

Causes worth a decision, not hidden by the numbers: the prompt (`extract/1`) lets the model create Topic and Event
entities freely, and the confidence rule of 5.3 holds only a part of them; recall of `about`/`mentions` needs
document-level links the rules do not make. Tuning the prompt and the thresholds is a separate card; nothing here
was tuned on the evaluation set.

`model-off/` and `model-on/` hold `report.md`, `report.json`, `report-published.md`, `report-published.json` and
`run.json`. `rules-only/` is the earlier evaluation of the rule output only (28 files, no sidecar).
