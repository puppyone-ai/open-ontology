# D-S2 author evidence

S2-D-01 is **partial**, not an AT-ENG-01 or support-matrix promotion.

## C1 delivery

`postgres::changes::PostgresChanges` implements `ChangeSource` on a separate
verified-TLS, read-only reader session. The caller supplies the DBA-created
slot/publication and a measured WAL-byte headroom requirement. Preflight
checks actual restart/confirmed positions and safe WAL bytes, not merely the
configured retention ceiling. Unknown/unlimited disk headroom fails closed.
This does not infer a time retention guarantee from a byte count.

- Negotiates pgoutput versions 1/2/3/4 on PG 13/14/15/16-18 respectively.
  Streaming and two-phase are not enabled: ordinary committed messages share
  the existing target parser's framing.
- Reuses `oo-pipeline/src/pg_current_capture.rs` by a private path module:
  no copied decoder, new crate dependency, root manifest or lockfile change.
  The LSN codec already shared with postgres-preview remains authoritative.
- Requires exact selected publication membership, no filters/column lists,
  primary keys, SELECT and REPLICATION without business-write grants or RLS.
  Root publications emit root identities; leaf publications must explicitly
  select their leaf identities. It never silently remaps partitions.
- Returns one complete transaction per batch, with one native typed Arrow
  image per change (delete images contain keys and nullable non-key fields).
  Converts logged text via source type casts and the existing binary decoder,
  never by re-reading a possibly newer business row.
- Preserves old primary keys on updates. Enforces row, raw-message, image-byte,
  incoming-frame and timeout bounds, with source protection and duty-cycle
  pacing. An over-budget transaction fails, never truncates.
- Missing/invalidated slots and expired positions explicitly require
  rebaseline. No slot/publication creation, deletion, advancement or ACK occurs.
  The durable coordinator must ACK after target commit. Until then replay is
  intentional and bounded; an arbitrarily large unacknowledged history is not
  supported by the in-memory batch reader.

The existing pipeline parser refuses unsupported messages (including
TRUNCATE). Unchanged TOAST values explicitly require rebaseline rather than
being turned into NULL. No-key/unique-only C1, streaming large transactions,
prepared transactions, standby/failover and target publication are not claimed.

## Live evidence

```sh
python3 testing/engines/postgres/run.py --suite changes \
  --versions 13,14,15,16,17,18 --run-id d-s2-c1-guarded-20261104
```

The small adversarial fixture is distinct from the S1 two-million-row scale
fixture. A separate fixture administrator commits UPDATE, DELETE, INSERT and
primary-key movement while the old snapshot's sink is held open, before the
chunk high watermark. Replaying the window corrects the buffered snapshot.
Three subsequent C1 cycles yield 2, 3 and 0 events; a native Arrow in-memory
target is compared with all current source rows after every cycle.

PG 18 additionally sets `idle_replication_slot_timeout=1s`, waits, checkpoints
and verifies the real `idle_timeout` invalidation and explicit rebaseline.
This is not a mocked catalog row. Invalidated slots are not recreated.

The runner starts one labelled container at a time, captures immutable image
IDs, source hashes, raw logs and hash manifests, then removes only its own
container. Credentials stay in git-ignored, mode-restricted evidence files.

## Validation and acceptance boundaries

Build/test outputs: `evidence/d-s2-20261104/`. Baseline: `da0becaa2`.
The full connector test run on that unmodified baseline fails
`parse_file_cli::parent_deadline_kills_the_worker_and_the_next_call_completes`
(`group_signal=rejected` rather than `sent` on this macOS host).
The unchanged `file_worker_parent.rs` also fails rustfmt at its Darwin match
guard. Both raw baseline failures are retained. Neither file is in this card's
write scope; neither was changed.

Window application is currently demonstrated by the fixture target, not wired
into coordinator-owned durable staging, publication or ACK. No claim is made
of crash recovery, continuous durable WAL spooling throughout a large initial
snapshot, Agent DB write metrics, new-generation suppression, or end-to-end
multi-binding C5-to-C1 handoff. Those are remaining acceptance work, not passes.

## C5 delivery and evidence

`PostgresEngine::inspect_c5` uses the existing `digest_range` for every issued
range. Positive timestamp hints force a read; absent/NULL hints cannot suppress
a digest. Recent ranges are checked first, not exclusively. Changed digests
(not just counts) schedule payload reads; the configured full-read cycle
schedules every range. Physical ctid plans are explicitly rejected as durable
cross-cycle ranges. The caller owns hint extraction, durable cycle state and
target publication.

Run `d-s2-c5-matrix-20261104` repeats the C1 checks and adds a two-range C5
baseline followed by three cycles on every PG 13-18 version. Same-count value
changes and same-count delete/insert replacement are detected without timestamp
hints. All ranges are checked despite a one-range recent hint. Positive hints
and periodic full-read fallback are also exercised.

| Cycle | Arrow payload bytes | Fixture target rows rewritten | Generation requested |
|---|---:|---:|---|
| Baseline | 2128 | 3 | yes |
| Value change | 1096 | 2 | yes |
| Delete/insert | 1096 | 2 | yes |
| No change | 0 | 0 | no |

These identical results across all six versions are **in-memory fixture target**
measurements, not Agent DB write accounting or a published-generation receipt.
The first C5 attempt incorrectly assumed a row budget of two plans two-row
chunks; the existing planner reserves half for growth. The corrected fixture
uses budget four to request two-row chunks. Data, oracle comparisons and the
two-range assertion were not weakened; the failed run is retained as
`d-s2-c5-first-20261104`.

## Final identity and resource guards

Final combined run: `d-s2-oracle-final-20261104`, PG 13.23, 14.24, 15.19, 16.15,
17.11 and 18.6. All six pass C1/window/C5 and applicable slot lifecycle tests.
The final checks additionally reject a complete transaction exceeding the row
budget without advancing the slot, and reject WAL from a dropped/recreated
same-name, same-column table by relation OID. Relation metadata is shared
between buffered events to avoid multiplying wide schemas by transaction size.
All six source hash maps match the delivered code and each other.

Reproduction:

```sh
python3 testing/engines/postgres/run.py --suite changes --versions 13,14,15,16,17,18 --run-id d-s2-oracle-final-20261104
cargo check --workspace --locked
cargo test -p oo-connectors --locked --no-fail-fast
```

The final suite includes 110 passing unit tests. The full crate run retains
only the separately proven baseline macOS parse-file failure described above.
Touched Rust files pass formatting; crate-wide formatting still reports only
the proven baseline `file_worker_parent.rs` match guard. No shared files,
Cargo manifests or Cargo.lock changed. No owned container is retained.
No support matrix or product-acceptance claim is made.

Lane H's integrated `tools/oo-test/comparison.py` is used by the runner, not
copied. Each version compares the window result, three C1 cycles, the C5
baseline and three C5 cycles: 8 typed/chunk-hash comparisons per version,
48 total, all equal. Source rows are SQL-ordered; the fixture has integer
business keys. These reports deliberately use comparison grade B rather than
claiming durable product transactional acceptance. Missing inputs or unequal
rows fail the runner. `H-comparison.json` and the helper's source hash are in
each version's evidence manifest. The earlier successful pre-oracle run
`d-s2-final-20261104` is retained, not substituted for this final run.
