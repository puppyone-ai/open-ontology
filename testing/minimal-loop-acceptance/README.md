# minimal-loop-acceptance

Independent card for MP-01a–d and MP-01 through MP-06. The frozen prompts are the six sealed bulk questions in `BULK-QUESTIONS.md`. It reads a fixed archive of `tools/minimal-product-loop`, `deploy/minimal-product-loop`, and `tools/pi-harness`, plus a pinned inventory, and, when that archive has a matching binary, runs `doctor`, `run`, `ask`, and `close`. `tools/agent-entry` is optional non-runtime packing. The copy-capability review is the independent MP-01a–c record with a live sibling case. `mp01_signed` may stay false until MP-01d is measured on the selected campaign. The preserved 410 import is a campaign label, not the pin for every fresh run. A question passes only when the model's final answer cites the audited query and the cited cells match; `id-overlap` may be a join that carries the count. A copy counts only when its discover and copy phases name a new import and the snapshot on the sealed manifest re-read after `run`. A `draft_ready` run stays measured after close rewrites the state to `released`. An operator fixture, a reader probe, and the a406 kit mount are readiness measurements. They do not pass the copy or the Pi questions by themselves.

Linux arm64 Rust 1.94 recipes live in `linux/`. Session `eef831aa-dba4-4af2-a78b-541bc9e0a415` uses `linux/a415/`. The recipes reuse the flag shape of `testing/product-benchmark/linux/smoke/launch.sh` at commit `6cec19fa15932fd5e2ee94070857ead464887f97`, blob `b79240d4e9b5be5146f75339e518667a4477e623`. The prepared fresh campaign config is `linux/a415/config/fresh-campaign.json`. Pipeline file paths stay outside git.

The crate has no third-party dependencies. `Cargo.lock` is the package itself. Do not run `cargo update` or `cargo generate-lockfile`.
