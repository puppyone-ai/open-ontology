# 25 · Super Ontology App（独立桌面应用）

> 决策：D85（独立 App）、D86（界面精度标准）、D87（产品定位与浅色设计语言）。本册取代 20 分册中“嵌入 Puppyone 的 Super Drive”的信息架构与视觉部分；20 分册的接口、状态、错误码、i18n 规则继续有效。

## 1. 定位

Super Ontology 把一个人或一个团队的文件和数据库，变成一份**有类型、有出处、随时间更新**的知识层，任何 Agent 都能凭一个令牌读取。App 是这件事的可视化入口；同样的能力在 `oo` CLI 中都能完成（D83）。

一句话：**放进资料 → 看到本体 → 交给 Agent。**

设计理念：

| 理念 | 在界面上意味着 |
|---|---|
| 出处优先 | 任何一条事实、一行 BRIEF，都能一步跳回原文锚点；没有出处的内容不展示为事实 |
| 本地优先 | 默认一切在本机；离开本机的动作（云存储、远端 Agent、模型）都明示并需要确认 |
| 可解释 | 状态、等待原因、被拦截的内容都说清楚“为什么”和“下一步” |
| 安静 | 界面不抢注意力；颜色只用来表达状态与唯一的主操作 |

## 2. 信息架构

左侧导航（固定宽度，可折叠）：

| 区 | 内容 | 主要接口 |
|---|---|---|
| 概览 Home | 本体规模（来源、实体、事实）、新鲜度、待确认数、下一步建议卡、最近变化 | health、drives、events |
| 来源 Sources | 所有来源一张列表：我的文件（默认托管文件夹）、本机文件夹、云存储（S3/OSS/COS/R2）、数据库；每个来源的同步状态与文件列表 | drives、files、upload、source add |
| 本体 Ontology | 实体（按类型、搜索、实体页：事实时间线 + 证据）、待确认、冲突 | entities、facts、review、constraints、search |
| Agent | 接入 Agent（令牌、MCP 配置一键复制：通用 MCP、Claude、Cursor、Codex 等）、上下文包（Share、BRIEF 预览、刷新与漂移）、访问记录 | agent tokens、shares、audit、ontology query |
| 设置 Settings | 引擎与运行时、模型、存储位置、隐私、关于与许可 | health、model config、runtime install |

底部状态条：引擎状态（运行中 / 启动中 / 不可用）与当前处理中的作业数，点击进入引擎详情。

## 3. 首次使用

1. 欢迎：一句话说明 + “开始”。在后台定位或安装 `oo` 并启动 `oo serve`（D83 自动选择运行时），进度内联显示。
2. 放进第一批资料：拖入文件即进入“我的文件”（零配置）；次要入口：选择本机文件夹 / 连接云存储 / 连接数据库。
3. 正在理解：按文件显示解析、抽取进度；可以先离开。
4. 看到本体：落到 Ontology，展示识别出的实体与第一条带出处的事实。
5. 交给 Agent：创建一个只读令牌，复制所选 Agent 的配置；附一条 `oo` CLI 等价命令。

## 4. 视觉语言（D87：浅色）

整体只做浅色主题（暗色本轮不做，token 结构为将来留口）。

| 项 | 规范 |
|---|---|
| 底色 | 画布 `#FAFAF9`，面板 `#FFFFFF`，内凹区 `#F4F4F2`；分隔线 1px `#E7E5E4` |
| 文字 | 主 `#1C1917`，次 `#57534E`，弱 `#A8A29E`；不使用纯黑 |
| 主色 | 一个强调色：墨蓝 `#2F4AD0`（悬停 `#2840B8`，浅底 `#EEF1FD`），只用于主操作、选中与链接 |
| 状态色 | 成功 `#15803D`、处理中 `#2F4AD0`、待确认 `#B45309`、失败 `#B91C1C`；均配浅底，状态以“点 + 文字”为主，徽章只给失败与需要处理 |
| 字体 | 系统 UI 字体（SF Pro / PingFang SC）；字号 12 / 13（正文）/ 15 / 20 / 28；行高 1.45；数字用等宽数字 `tabular-nums` |
| 间距 | 4px 网格：4 / 8 / 12 / 16 / 24 / 32 / 48 |
| 圆角 | 6（控件）/ 8（卡片、菜单）/ 12（对话框） |
| 阴影 | 只给浮层：菜单、对话框、Toast；面板之间用分隔线不用阴影 |
| 图标 | 单一线性图标集，16px（列表、按钮）与 20px（导航），描边 1.5px，`currentColor`，统一视觉框；与文字垂直居中并像素对齐 |
| 动效 | 120ms（悬停、按下）/ 200ms（展开、面板）`cubic-bezier(0.2, 0, 0, 1)`；尊重“减少动效” |
| 控件 | 高 28（紧凑）/ 32（默认）；输入框有占位、帮助与错误三态；焦点环 2px 主色 30% 透明 |

组件实现可以复用 Puppyone Desktop（Apache-2.0）的工程原语（菜单、对话框、虚拟列表、Tooltip 等），但外观一律由本册 token 驱动，不沿用其品牌、配色与图标。

## 5. 精度验收（D86）

## 7. CLI 全功能与本体图谱（D88）

### 7.1 CLI 等价

| CLI 能力 | App 位置 |
|---|---|
| `oo docs upload`、`oo source add fs|s3|oss|cos|r2` | 来源 › 添加来源 |
| `oo source add <数据库>`、导入与刷新（全部现有数据库连接器） | 来源 › 添加来源 › 数据库；来源详情显示表、导入进度、最近一次刷新 |
| `oo init`、流水线运行与发布、`oo freshness` | 来源 › 数据库详情；概览的新鲜度 |
| `oo query`、`oo tables`、`oo describe`、`oo knowledge search|cat` | 本体 › 查询（只读 SQL 带校验）、表与知识检索 |
| `oo ontology search|entity|query` | 本体 › 实体、搜索 |
| `oo agent token`、`oo mcp-config`、`oo mcp` | Agent › 接入 |
| `oo serve`、`oo docs runtime`、`oo check`、`oo doctor` | 设置 › 引擎与诊断 |

每个操作完成后可展开“等价命令”，一键复制。

### 7.2 本体层文件

本体层是 YAML 文件。本体 › 文件：按版本列出 YAML（只读、语法高亮、行号、复制），两个版本之间的差异视图，导出为文件夹。

### 7.3 本体图谱（2026-11-19 修订：精确生长）

owner 反馈：细胞形态发糊、不够现代、不贴主题。改为“精确生长”：保留“随数据生长、随变化而动”的理念，去掉有机模糊的质感，用清晰的几何表达“文件与数据库汇成一个有出处的本体”。

- 画布：暖白底上极淡的点阵网格（8px 间距，1px 点，约 6% 不透明），给空间感与尺度；无渐变、无模糊、无阴影光晕；所有图形按设备像素对齐，描边 1px（2x 屏 0.5 逻辑像素对齐到物理像素）。
- 形状编码来源：文档来的实体为圆点，数据库来的表/实体为圆角方块（2px 圆角），两边汇合的同一实体为圆点外加方框细环——一眼看出“文件 + 数据库 → 一个本体”。
- 分组：类型或来源分组画成以成员凸包为基础的圆角轮廓（1px 描边、2–4% 填充），组名放在轮廓左上外侧，13px 字重 500，计数用等宽数字放在组名后的弱色里；不再用大圆细胞。
- 颜色：节点填充用 25 分册 §4 的类型色调（墨蓝系低饱和）实色，1px 白色描边隔开；只有选中/聚焦用强调色墨蓝。
- 连线：1px 直线，默认 10–14% 不透明；有方向的关系在放大后显示 4px 小箭头；聚焦时相邻连线变墨蓝 60%，其余降到 4%；组与组之间的汇总线按数量 1–3px。
- 生长动效：新节点从 0 缩放到 1（200ms，cubic-bezier(0.2,0,0,1)），连线从源到目标“画出”（200ms）；变更为节点外一圈 1px 墨蓝细环由 1x 扩到 1.6x 并淡出（400ms）；撤回为缩小淡出；新版本发布时左下角版本号数字滚动 + 新增节点依次出现（每个错开 16ms）。不再有持续漂移与呼吸——静止时画面完全静止。
- 标签：缩放到足够大才显示实体名（12px，背景同画布色的 2px 描边防遮挡），始终清晰。
- 交互、性能、可访问性与原要求相同（1,000 节点 60fps、10,000 可用、减少动效时去掉动画、键盘列表等价视图）。
