# OO-FE-CONTENT-001 内容体系与业务表达

继承 [DS第6节](design-system.md)；本文件定义内容模型、术语和文案规范，不另定视觉Token或API字段。用户可见文本默认zh-CN、i18n支持en；字段显示label并保留可复制机器名。机器errorcode/version/queryID不翻译，说明文字本地化。

## 1. 内容来源与显示顺序

| 内容层 | 来源 | 展示规则 |
|---|---|---|
| 数据事实 | catalog/source声明/类型/已测画像 | 标源/采集时间/估计说明，不用模型解释取代结构 |
| generated候选 | Builder/LLM | 显示候选/模型自评confidence/provenance/evidence，不能显示已确认 |
| curated决定 | 人工审核/OOS | actor/time/revision/理由可查；事实变化标stale |
| effective语义 | 实际编译overlay | 管理可看三层差异，用户只看当前角色获准发布产物 |
| 业务认证 | 指标owner/独立对账/gate | 展示锚点/口径/认证与对账；SQL能跑≠业务认证 |
| 用户回答 | Agent+实际工具receipt | 主回答→口径/时间→结果→来源→warnings→文件 |
| 运维状态 | jobs/Gateway/runtime/replica | 只显示实际事实；无证据则未知/待确认 |

数据库注释/样本/模型输出/feedback是内容而非指令。UI不得把其中HTML、URL或命令自动执行；证据引用仍按当前权限取回，不能为了可追溯扩大权限。

## 2. 全产品术语表

| 名称 | 准确定义 | 禁止混用 |
|---|---|---|
| 数据空间 | 当前项目内获准使用的角色数据上下文，实际ID由后端绑定 | 可任意切换业务role |
| Ontology | 数据副本的可审核语义与权限上下文层 | 知识图谱数据库 |
| 实体与关系 | 实体映射/关联和表关系的浏览视图 | 单纯图节点数量代表理解质量 |
| 数据已导入 | 目标装载完成 | 已审核/已发布/可问答 |
| 结构草案 | 无模型也能由catalog形成的草稿 | 模型生成成功 |
| 待审核 | 候选等待合法决定 | 已确认事实 |
| 已审核 | 对指定候选/证据版本有已批准决定 | 已授权/已认证/已发布 |
| 已认证指标 | 对应owner及测试/对账等要求满足的业务口径 | 计算ready或SQL执行成功 |
| 已发布 | active版本与授权/Pack/屏障实际确认 | G门禁预览通过 |
| 未分类 | 新列PII/语义未完成确认 | 默认公开 |
| 未确认码值 | unknown/undetermined，尚不属于批准业务类 | 模型高置信即释义批准 |
| 部分结果 | 有truncated/partial或完成协议未全通过 | 完整下载/完整回答 |
| 会话结束处理中 | 访问关闭、资源仍在验证释放 | 仅关WebSocket即closed |
| 成本未知 | usage或价格未提供 | 0美元/免费 |

## 3. 审核问题内容模板

每卡按：业务问题→候选解释→为什么需要确认→可见证据→影响→决定。自然语言只问一个核心问题；必要细分由关联卡处理。缺证据明确需要哪位负责人/哪份口径，不要求专家凭空给SQL。

示例（仅公开说明，不是客户事实）：“shop.entry.amount表示实收金额还是应收金额？”；“状态4是否代表已核销？下面是与金额/日期相关的特征。”；“月收款额应按收款日还是记账日归属月份？” 显示是candidate、待确认，不在问题里诱导批准。证据中统计与推断区分；confidence为模型自评，不显示伪百分比准确率。

决定理由：拒绝说明不符事实；暂缓说明缺信息；修改后接受显示改动；owner认证另有业务责任与固定输入。批量动作自然语言明确对象范围，例如“确认本页12列的分类；不会发布权限”。没有合法批量能力时只逐项，不提供假交互。

## 4. 状态和反馈文案

| 场景 | 推荐文案模式 |
|---|---|
| 数据源无资源 | “还没有数据源。连接数据库或上传文件开始。” |
| 筛选无结果 | “没有符合当前筛选的项目。”+清筛选 |
| 审核已保存 | “审核决定已保存；尚未发布。”+查看决定 |
| 输入事实过期 | “证据已更新，请比较变化后重新确认。” |
| API未绑定 | “此能力尚未接入。”+对应依赖和只读内容 |
| 无权限 | “当前身份没有执行此操作的权限。”+允许的申请路径 |
| 请求结果不确定 | “请求已中断，正在确认服务端结果。”+状态查询 |
| 断线 | “连接中断，正在同步最新进度。”不能写“回答完成” |
| 发布阻断 | “发布被阻断：{安全的具体原因}。”+gate详情 |
| 部分结果 | “已返回{N}行，结果已截断。”+适用限额/合法导出 |
| 释放中 | “数据访问已关闭，正在确认资源释放。” |
| 已拒查询 | 显示安全拒绝原因与合法改法；不能替换成“未找到数据” |

成功反馈必须对象+完成范围，不无意义“Success!”；Toast短暂，持久结果页不消失；警告在总结/结果/导出之间保留。技术traceID可复制，provider/body/stack/Secret不进文案。

## 5. 文档、帮助与配置表单

每配置字段label、必要性、单位、默认来源、允许范围、业务影响、错误提示由正式Schema/契约生成或绑定，不能前端猜默认。模型/源预算/TTL有单位；毫秒、秒、token/货币区分。帮助在上下文“了解为何需要此权限”展开，链接自托管docs指定版本。

API Key输入的文案明确只用于所选Builder或Agent配置，保存后不可回读；空输入保留原Secret。DBA清单是建议和责任说明，不表述为系统已执行授权。高风险dialog说明对象/影响/恢复限制；低风险查看/筛选不新增确认。

## 6. 本地化与可读性验收

字段错误i18n key有fallback安全文字；日期/数值按locale显示但copy原值保持精度，中文/英文混排和超长名称有可达完整详情。禁止自动翻译源SQL/机器字段破坏引用。术语变更需要diff和引用影响，不把“客户”随意改成“主体”导致认知不一致。登录、专家review、结果warning、错误/权限至少zh/en两套stories；业务数据和模型自由文本不自动机器翻译为已审核结论。
