# 测试加速方案：T0–T10 从“每次全量”改为“分层证明”

> 状态：草案，待 owner 确认后执行。日期 2026-11-12。
> 目标：日常回归的墙钟时间压缩到现在的 1/10 以内，同时**证明**加速后的套件抓得住所有历史缺陷，覆盖面不降。

## 0. 现状：时间花在哪里

最近一次固定 SHA 回归（s6h01c，单机，四路并行）各项耗时：

| 项 | 耗时 |
|---|---:|
| Oracle T7（23/21/11） | 14,230 s |
| PG 矩阵 T0/T1/T8（13–18） | 8,060 s |
| PG T7（13–18） | 7,601 s |
| Oracle 矩阵 T0/T1/T8 | 7,419 s |
| PG T3/T4 | 6,908 s |
| MySQL T7 | 5,585 s |
| MySQL T3/T4 | 4,790 s |
| Oracle T3/T4 | 4,363 s |
| MySQL 矩阵 | 4,166 s |

串行合计约 17 小时，四路并行墙钟约 5–6 小时，还因此把机器跑到 OOM。

拆开来看，真正验证产品行为的时间占比很小，大头是四类**重复劳动**：

1. **反复造库。** 每个套件、每个版本都新起容器、重新灌 200 万行或 200 张表，Oracle 光启动和建库就要几分钟。
2. **数据规模与断言无关。** T1、T2、T3、T4、T7 的断言是“逐行相等”“语句类别合规”“位点不回退”，与 200 万行还是 2 万行无关。规模只对 T10（生产影响）和 T8 的长窗口有意义。
3. **版本维度全量相乘。** 同一引擎的 6 个版本把同一套语义各测一遍，但真正随版本变化的只有方言、目录、CDC 能力这一层。
4. **故障注入靠真实等待。** T3 通过重启容器、断网、等超时、等日志过期来制造故障，时间都花在 `sleep` 和恢复上。

## 1. 核心思路：把“证明什么”和“在哪证明”分开

每个断言只在**能证伪它的最小环境**里证明一次，再用一个**缺陷回放闸门**证明加速后没有漏网。四层：

| 层 | 证明什么 | 环境 | 频率 | 目标耗时 |
|---|---|---|---|---:|
| L0 契约层 | 引擎无关的产品逻辑：裁决、编译、Gateway 准入、发布身份、重放幂等、哈希契约 | 进程内 + 一个共享 PG 目标库，无源库容器 | 每次提交 | < 3 min |
| L1 方言层 | 每个引擎×版本的版本相关能力：目录发现、类型映射（含宽 decimal）、快照读一致性、CDC 起点、审计语句类别 | 预制快照的源库，小规模夹具 | 每次 PR，按影响面选择 | < 15 min |
| L2 端到端层 | 从安装到首答的完整链路，每引擎一个代表版本：T0→T9、quickstart | 预制快照 + lite 栈 | 每次 PR | < 15 min |
| L3 规模与扰动层 | 200 万行、长时 T7、T8 长窗口、T10 生产影响、真实长等待的故障 | 当前全量环境 | 夜间轮转、发版前一次全量 | 不变，但移出日常 |

日常回归 = L0 + 受影响的 L1 + L2，目标墙钟 ≤ 30 分钟，约为现在的 1/10。L3 不砍，只是不再每次跑。

## 2. 七个具体手段

### 2.1 预制快照源库（省掉造库）
- 每个引擎×版本只灌一次数据，导出为**带标签的镜像或卷快照**：PG/MySQL 用数据目录快照，Oracle 用已开库的数据文件。用 Docker volume clone 或 APFS clonefile 做写时复制，秒级拿到干净副本。
- 快照以“夹具生成器哈希 + 镜像摘要”为键，夹具代码一变就自动重建，不会用陈旧数据。
- 预计：Oracle 每次省 3–6 分钟启动和建库，PG/MySQL 每次省 1–2 分钟。

### 2.2 一个版本一个容器，套件共用（省掉重复启动）
- 同一引擎版本的 T0/T1/T2/T4/T7/T8 共用一个源库容器，每个套件用独立 schema 加独立复制槽或位点隔离。现在每个套件各起一次。
- 只有会破坏实例状态的用例（重启、清日志、resetlogs）才单独克隆一份快照。

### 2.3 规模与断言解耦（省掉灌数据和全量比对）
- 正确性用例改用**边界结构化的小夹具**：几千行，但用 `--chunk-rows` 压小，逼出与 200 万行相同的分块数、跨块边界、空块、末块不满、LOB、宽 decimal、无键表和分区表。
- 这样得到的分支覆盖和 200 万行一样，耗时是百分之一。200 万行只留给 L3。
- 检验办法：对比 2 万行与 200 万行两次运行的产品分支覆盖（Rust `-C instrument-coverage`），差集必须为空，不为空就补夹具形状。

### 2.4 版本按能力分等价类（省掉版本乘法）
- 从 `rules.rs`、支持矩阵和各连接器的版本分支里，自动提取“哪些代码路径随版本切换”。例如 Oracle 12.1 的 STANDARD_HASH、12.2 的列排序规则、FETCH FIRST；PG 15 的 publication 行过滤；MySQL 8.0 的不可见列。
- 每个等价类只在一个代表版本上跑全量 L1，其余版本只跑**能力探针**：连接、目录、类型映射、一次快照、一次增量，约 1–2 分钟。
- 代表版本按天轮换，一周内每个版本都当过一次代表，避免某个版本长期只被探针覆盖。

### 2.5 确定性故障点（省掉真实等待）
- 产品内加编译期开关的 failpoint（只在测试构建里存在，发布构建里不编译进去），例如“块写一半”“发布前”“提交前”“读游标中途”，由测试直接触发中断，不再重启容器、断网后干等。
- 断网用 toxiproxy 精确注入，超时参数在测试里调小；日志过期、slot 失效用管理语句直接制造，不靠等保留期。
- 每个 failpoint 都要配一条 L3 的真实故障用例，夜间验证两者结论一致，防止只是自说自话。

### 2.6 影响面选择（只跑受影响的格子）
- 建立“代码路径 → 套件格子”的映射：用 L0/L1 的覆盖数据自动生成，再加人工规则兜底（改了 `oracle/**` 就跑 Oracle 全部格子，改了 `engine/**` 就全跑）。
- PR 只跑受影响的 L1 格子。合并到主干后跑全部 L1 加 L2。

### 2.7 内存感知调度（不再 OOM）
- 调度器按容器的内存预算装箱，例如 Oracle 4 GB、PG 1 GB、lite 栈 3 GB，在 Docker VM 内存的 70% 以内并行。替代现在固定四路并行。
- 把这次 OOM 的教训变成硬规则。

## 3. 怎么证明“效果和现在一样”：缺陷回放闸门

加速最大的风险是漏测，所以必须有客观证据，而不是靠判断：

1. **历史缺陷语料。** 把台账里所有真实抓到过的缺陷还原成可注入的变异，每条对应一个 commit 的反向补丁。例如：
   - Oracle 11g worker 错误码丢失
   - C1 重用 run id 被当作重放
   - MySQL 5.7 latin1、RENAME 语法
   - Decimal256 进位截断
   - PG 并行查询设置未审核
   - 21c 短窗口占空比
   - 发布身份 0135/0136
   - 隔离表 stale 语法
   - 审计越权授权
   - 摘要哈希不一致
2. **闸门规则。** 对每条变异分别跑一次加速套件，必须全部被抓住（失败）。任何一条漏网，加速方案就不能上线，补用例后重测。
3. **差分对照。** 上线后前两周，加速套件和全量套件对同一 SHA 并行运行，结论逐格比对。不一致必须解释。
4. **覆盖不降。** L0+L1+L2 的产品代码行与分支覆盖，不得低于当前全量套件的覆盖。
5. **持续新增。** 以后每发现一个新缺陷，修复时同时把它的变异加进语料。

## 4. 预期收益

| 场景 | 现在 | 加速后 |
|---|---:|---:|
| 日常提交 | 无（只能整套全跑） | L0 < 3 min |
| PR 回归 | 5–6 h 墙钟 | ≤ 30 min（L0 + 受影响 L1 + L2） |
| 合并后全量 L1+L2 | — | ≤ 45 min |
| 发版前 | 5–6 h | 不变，L3 全量一次，作为最终证据 |

## 5. 实施顺序

1. **测量先行（半天）。** 给现有套件按阶段打点（起容器、灌数、产品运行、比对、清理），确认时间分布，作为基线。
2. **快照源库 + 共用容器（2.1、2.2）。** 改动最小、收益最大，预计单独就能快 3–4 倍。
3. **小夹具 + 覆盖差集检验（2.3）。**
4. **缺陷回放闸门（第 3 节）。** 在大幅砍时间之前先建好，后面每一步都用它验收。
5. **版本等价类与轮换（2.4）、影响面选择（2.6）、内存调度（2.7）。**
6. **failpoint 与 toxiproxy（2.5）。** 涉及产品代码，最后做，并配夜间真实故障对照。

每一步都要求：缺陷语料全部被抓住、覆盖不降、和全量结论一致，才进入下一步。

## 6. 不变的东西

- 发版前仍跑一次完整 L3，固定证据格式不变，作为对外“已验证”的依据。支持矩阵的等级只认 L3 和 L1 代表版本的证据。
- 安全相关断言（审计语句类别、权限、注入、只读）在 L1 每个版本都保留，不进入等价类抽样。
