# Native admission and captured batch binding
Coordinator implementation contract, 2026-10-10. Scope: controlled single-operator preview; public/untrusted Gateway authorization is unchanged.
Problem: native import e7689831 hard-codes two fixture decisions with empty batch lists and requires Arrow digests inside strict oo.source-admission.decision/v1. Existing decisions do not declare batches. That creates a circular implementation dependency, not an external prerequisite.
Keep oo.source-admission.decision/v1 unchanged. Introduce a separate oo.source-admission.capture-binding/v1 artifact with source_id, native engine, generation, snapshot identity, report/config/decision hashes, actual driver and capture receipt identities, and selected table/schema/row-count/Arrow-file hashes.
The source adapter produces this binding from actual capture and actual admission; it is not a replacement decision or an admitted=true assertion. Policy is recomputed using the frozen source-admission implementation (direct library or the exact verified CLI). If using a CLI, its path/digest are trusted runtime configuration, never a client-selected executable or shell command.
The importer verifies a private operator/runtime-approved binding registry or plan, supplied outside the data manifest. The registry's expected digest is trusted runtime configuration, not a client-controlled assertion beside the payload. A new captured batch is registered as data/configuration, not by recompiling hard-coded production pins. Public users cannot select files/registries/configs/validator executables.
Recompute/verify policy from report+config, bind its exact decision and identity to the selected capture, verify all Arrow and schema digests and rows, and compare source/engine/snapshot/selected objects against the approved binding. Non-admitted, unknown/cross-engine/writable scope, missing settings, wrong driver/source/batch/schema/rows, forged or mutable approval, empty/truncated/unsupported payload and target errors fail closed before publishing/sealing. No seed from GOLD, no synthetic input digest, no retagging as PG/MySQL.
Registry/binding files contain no credentials. Source passwords remain in existing private refs. Imported native data keeps its actual engine separately from PG storage. Necessary metadata provenance survives normalization; unsupported native types are refused honestly.
A complete proof must use a genuine fixed Oracle or ClickHouse capture and actual native policy inputs, physically load typed rows to an independent PG target, seal the real run, query independently and verify rollback/no partial seal on failures. Policy replay and unit tests alone are not the capability.
This is a repair of the shared native import contract, not a new accepted development unit or target grade. Connected source products and this critical boundary are reviewed at fixed SHA.
