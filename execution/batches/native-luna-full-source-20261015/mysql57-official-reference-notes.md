# MySQL 5.7 compatibility: official references and minimal scope

2026-10-16. Human requires actual5.7 support in the existing MySQL source family. Source discovery used AnySearch code.doc (library=MySQL). Its extract returned extract_failed for all three discovered URLs; the same primary pages were then read with the browser tool. Search snippets alone are not acceptance evidence. No source credentials or internal endpoints were searched.

- [MySQL5.7 binary logging options](https://dev.mysql.com/doc/mysql-replication-excerpt/5.7/en/replication-options-binary-log.html): explicit log-bin and server-id; ROW/FULL before-after images; expire_logs_days is measured in integer days, default0 means no automatic removal. Normalize actual retention to seconds at the existing preflight boundary; use only supported version-specific fixture configuration, never source writes from the runtime reader.
- [MySQL5.7 binary log coordinates](https://dev.mysql.com/doc/mysql-replication-excerpt/5.7/en/replication-howto-masterstatus.html): use the version-appropriate existing status statement. The current SHOW BINARY LOG STATUS-only helper must handle5.7 SHOW MASTER STATUS. Read statement and permissions guidance only: the original CDC-first product contract is not replaced by the manual locking snapshot recipe.
- [MySQL5.7 GTID restrictions](https://dev.mysql.com/doc/mysql-replication-excerpt/5.7/en/replication-gtids-restrictions.html): retain transactional InnoDB fixtures and GTID consistency; avoid CREATE TABLE SELECT and transaction-scoped temporary table setup. Existing explicit DDL plus transactional DML is sufficient.
- [Official mysql5.7.44 image](https://hub.docker.com/layers/library/mysql/5.7.44/images/sha256-dab0a802b44617303694fb17d166501de279c3031ddeb28c56ecf7fcab5ef0da): linux/amd64 image. Author must freeze actual resolved index/platform/image identity from Docker, not copy a page digest into the runtime receipt. Actual emulation is disclosed separately from native-platform certification.

Avoid legacy refman/5.7 links silently redirecting to9.7; the official mysql-replication-excerpt/5.7 pages retain the requested version.

Code findings, not implementation claims: tools/mysql-preview/src/source.rs, customer.rs and c1.rs contain major8 checks; c1 preflight reads the8.x retention variable, c1_materialize consumes normalized seconds. The author independently found status and utf8mb4_0900 fixture differences. Extend these existing boundaries minimally, prove actual5.7 types/events/TLS/permissions/capture and full downstream chain; no generic dialect framework or C5 downgrade. Source-side catalog detection and real tests decide compatibility. RDS5.7 is a separately unverified deployment variant; owned5.7 fixture success does not certify customer RDS.

TLS follow-up: [MySQL bug82935](https://bugs.mysql.com/bug.php?id=82935) reports5.7.15 ECDHE negotiation and was later closed using9.6 trunk. This is background, not proof of5.7.44 behavior or a patch to apply. Author measured the actual5.7.44 fixture: verified OpenSSL TLS1.2 succeeds with DHE while forced ECDHE fails. [mysql_async feature documentation](https://docs.rs/mysql_async/latest/mysql_async/#features) documents its existing native-tls-tls backend; use the actual pinned crate feature, do not upgrade just to match latest docs. Keep a single standard backend and full CA/hostname checks; prove positive and wrong-identity refusals plus8.4 connection compatibility before claiming support.
