# SourceEngine T1 hook

The existing lane-H hook API is unchanged:

```sh
tools/oo-test/oo-test matrix --engine postgres --versions 17 --suites T0,T1 \
  --hook T1=tools/oo-test/t1.py
```

Build `tools/oo-load` first (see its README). The hook verifies fixture ownership,
uses a separate fixture-admin connection for TLS, reader grants and the writer,
and uses only the read-only reader in the product. It starts one fresh Agent DB.
When H's source has no published port, a loopback stdio TCP relay uses `docker
exec` into that labelled fixture; no extra database or network container exists.

For lane M's standalone matrix, using H's unchanged generator and seed API:

```sh
python3 tools/oo-test/t1.py --engine postgres --versions 13,14,15,16,17,18 \
  --run-id m-t1-postgres
python3 tools/oo-test/t1.py --engine mysql --versions 5.7.44,8.0.44,8.4.7,9.5.0 \
  --run-id m-t1-mysql
python3 tools/oo-test/t1.py --engine oracle --versions 23ai,21c,11g \
  --worker-image <local-thick-worker-image-id> --run-id m-t1-oracle
```

Default fixture size is 2,000,000 events and 200 small tables, plus every table
from H's generator, including the 300-column and type-edge tables. `--scale`
and `--tables` are diagnostic reductions, not scale acceptance. Every discovered
fixture table is required. Failure on a type or table fails T1; no exclusion is
added to make it pass. All matrix versions are attempted even after a failure.

An admin writer performs insert, update, primary-key update, delete and growth.
PostgreSQL uses one persistent admin session and requires a per-cycle commit
acknowledgement, avoiding a new Docker API exec request for every cycle. A lost
connection or missing acknowledgement still fails the suite.
The first `oo-load` runs concurrently. The writer then quiesces and a new run
recaptures every table, the conservative correction fallback. A third invocation
resumes that corrected run; receipt replay must not increase target write bytes.
Comparison uses H's `comparison.compare`, with source-defined key order,
canonical numbers/JSON/empty semantics, ordered chunk hashes and first differing
keys. No-key fixtures are ordered by all source values. Consistency is `B`
(quiescent final comparison); this is not a claim of online CDC convergence.

Oracle 11g requires a trusted existing thick-worker image; only a new labelled
worker container is created and removed. Set `OO_TEST_ORACLE_WORKER_IMAGE` when
using H's hook API. The shared Oracle engine currently rejects LOB columns;
the suite does not remove H's LOB fixtures. Oracle comparison similarly refuses
unimplemented types rather than truncating them.

T8 samples source-side reader sessions through a separate fixture-admin
connection around each load and resume. It queries MySQL processlist,
PostgreSQL pg_stat_activity, or Oracle v$session. The target adapter records
committed logical tuple bytes, including abandoned plans and partial loads.
No model is called. The target publishes local views, not Gateway releases.

Duty is the time-weighted sum of active reader sessions divided by load wall
time, not duty divided by connection count. Sampling waits 200 ms between
queries; raw timestamps expose the actual cadence. These are sampled peaks
and duty, not a continuous upper-bound proof. Missing/failed observations fail
closed. Each invocation must stay within the effective ReadBudget's duty limit
(currently 25%). ReadBudget has no connection-count field: the harness enforces
one MySQL/Oracle reader and two PostgreSQL readers (engine plus snapshot owner)
as a separate explicit topology budget. There is no configured target-byte cap.
T8 failure makes the matrix command fail even when T1 comparisons pass.

`t1-images.json` supplements H's pins with the exact MySQL card versions;
the shared image lock is not modified. TLS material is generated locally,
installed only through the owned fixture-admin connection, and removed on exit.
The product reader retains SELECT/SHOW VIEW only.

Evidence lives under the supplied run ID. Failed runs are retained. Cleanup
checks both lane and run labels, and removes only this invocation's containers,
volumes and generated secret directories. Images are never deleted.

Database JSON output is restored to typed dates, timestamps, bytes and finite
floats before calling the shared canonical oracle. Decimal parsing preserves
negative zero until float conversion. Nonfinite floating-point values require
a wire-bit comparison, and Oracle submicrosecond values require an extended
temporal oracle; these cases fail explicitly instead of rounding.

When auditing earlier captures after a comparison change, preserve the original
reports and replay the retained successful SQL outputs:

```sh
python3 tools/oo-test/recompare_t1.py --evidence evidence/m-t1-postgres
```

This makes new `typed-comparison/` reports and checksum manifests, binding each
report to its three original command outputs. It does not reconnect to a
database, rerun a loader, or replace earlier evidence. An existing audit
directory is refused rather than overwritten.
