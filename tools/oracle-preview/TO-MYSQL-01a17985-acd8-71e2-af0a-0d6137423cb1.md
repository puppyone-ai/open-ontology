## Frozen transaction checkpoint envelope

Protocol: `oo.oracle.debezium-checkpoint/v1`.

Required fields: engine/source identity digest/epoch; pinned Debezium and JDBC
digests; connector partition + opaque offset-store bytes/digest; snapshot SCN;
transaction ID; commit SCN; per-event redo thread, SCN, rs_id, ssn and total_order;
END expected count; ordered event/payload digest; immutable capture sequence.

The capture sequence is a durable local application-order key, **not an Oracle
SCN or fabricated GTID**. Two transactions can share a commit SCN. The shared
adapter must preserve a tie-safe checkpoint, validate replay by transaction and
payload identity, and never discard the opaque connector offset in favour of
`current_scn`. Target ACK requires complete transaction + successful atomic apply.
HTTP spool ACK only means durable capture.

Debezium snapshot/log cut (real `source.scn`, not a guessed L0), exported as
bounded Arrow parts. The independent native Oracle reader checks those bytes.
