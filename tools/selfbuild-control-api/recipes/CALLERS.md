# One self-build recipe

Sources 39 MariaDB, 40 ClickHouse, 43 Doris, 44 OpenSearch, 45 StarRocks, 46 PostgreSQL, 04 Oracle, 06 MySQL, and 41 MongoDB call the same control API. They do not each carry a copy of this crate.

The caller prepares a server-side sealed bundle and a project whose `source.tables` match that catalog. The API reads the bundle. It does not open the model bearer, does not open the source password, and does not spawn a foreign builder when `sealed_bundle` is set. `compiled_pack` stays `not_published`. There is no publish route on this service.

## Create

`POST /control/v1/builds` with cookie `__Host-oo-session`, `Origin` equal to a deployment origin, and `X-OO-CSRF` equal to the current identity token.

```json
{
  "allowance_id": "entry_allow",
  "config_commit": "7171717171717171717171717171717171717171717171717171717171717171",
  "identity_revision": 1,
  "idempotency_key": "ledgercreate000001",
  "llm_secret_ref": "secret://llm/sealed",
  "project_id": "ledger",
  "source_ref": "entry_src"
}
```

Those seven fields are the whole body. `202` returns `stages`. The same key and body replay. A different body with the same key is `409 idempotency.conflict`.

## Stages and overlay

`GET /control/v1/builds/{build_id}` returns `stages[]` with `stage`, `status`, `output_sha256`, and `detail_code`. `GET /control/v1/builds/{build_id}/overlay` returns generated, curated, and effective YAML hashes. Curated text is posted as JSON, in the `yaml` field, to `POST /control/v1/builds/{build_id}/curated`.

## Maintenance

`POST /control/v1/builds/{build_id}/maintenance`

| trigger | extra field |
| --- | --- |
| `table_ready`, `scheduled`, `manual` | none |
| `schema_changed` | `fact_edit` object `{dataset, column, data_type}` |
| `feedback` | `note` string, at most 200 characters |

`feedback` appends a candidate. It does not change generated or curated YAML.

## Review, confirm, role pack, gates

`POST /control/v1/builds/{build_id}/review` body keys: `binds_fact`, `decision` (`confirmed` or `rejected`), `identity_revision`, `idempotency_key`, `name`.

`POST /control/v1/builds/{build_id}/confirm` body keys: `columns`, `identity_revision`, `idempotency_key`. `business_owner_signed: true` is `400 malformed`. A successful confirm still records `business_owner_signed: false` and `signer_class: control_plane_test`.

`POST /control/v1/builds/{build_id}/role-pack` body keys: `identity_revision`, `idempotency_key`, `policy_version` (`oos/v1`), `role`. `GET` the same path with `?role=`.

`POST /control/v1/builds/{build_id}/gates` body keys: `identity_revision`, `idempotency_key`.

`POST /control/v1/builds/{build_id}/publish` is not registered.

## Negative cases

- No cookie: `401 unauthenticated`. No Ready and no role pack.
- `generation.outcome` `model_unauthorized` or `model_timeout`: S5 failed, cards `ready: false`, role pack `409 pack.refused`.
- Curated YAML with a tab, a duplicate key, or `data_type`: `400 malformed`. Generated bytes stay put.
- S10 not `succeeded`: role pack `409 pack.refused`. A stale column on a finished S10 is also `409 pack.refused`.
- Personal or unknown PII: `409 pii.withheld` or `409 pii.unknown`. The column is not auto-approved.
- Reviewer `review.decide` cannot compile a pack (`403`). Auditor `audit.read` cannot create a build (`403`).
- A second identical maintenance or role-pack body with a new idempotency key is a cache hit and makes `llm_calls: 0`.

`linux/live.sh` is the fixed runner for this crate. Point `sealed_bundle` at the caller’s own read-only bundle directory.

Sources 39, 40, 43, 44, 45, 46, 04, 06, and 41 keep this one recipe. They do not copy the service. A fixed PostgreSQL capture is selected by the server project field `source_protocol`, not by a new public operation and not by a per-source binary. The create body stays the seven fields above. `recipes/source_adapt.py` is that server configuration for the fixed 100050-row capture: original catalog, profile, and semantics bytes are copied, type basis files stay hashed, and OID 17 stays `bytea` with no OOS `data_type`. S5 on that path is `awaiting` / `model.blocked` when the bearer file is absent, and the service does not spawn. A present bearer file uses the existing `pg-builder` `approve` / `generate` / `curated` argv. A missing binary or missing seal and cards inputs fails closed (`builder.absent` or `builder.inputs_absent`) and does not mark Ready. `structural_draft` in the bundle file is not a model success. A changed protocol string, a forged `data_type` on a basis column, or `sampled: true` is refused before a pack exists. `linux/live.sh core-bind` is the runner that compiles this crate against fixed `oo-core` `983577c9b89453b08ab4e1a02cab88df78c3e005`.
